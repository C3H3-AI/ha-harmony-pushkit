# Harmony PushKit

这是一个非常早期的实验性 Home Assistant 集成，后续可能发生较大变化。

## 实现方式

HarmonyOS App 仅通过 `mobile_app` 注册上报 `app_data.pushkit_token`。集成发现有效 Token 后，为对应设备创建通知实体；发送时由用户选择该通知实体。

集成从本地 AGC 客户端凭据获取 Connect API AT，再携带该 AT 请求云函数签发短期 PushKit 票据，最后使用该票据调用 Push v3 接口。各层票据在有效期内缓存，并在使用前检查是否即将过期。

默认只发送通知。启用“App 落库”后，通知会额外写入 App 的通知历史。

## 为什么这样实现

我们不希望向最终用户分发具备过大权限的服务账号 JWT。云端签票服务可以限制签发能力和票据有效期，并让后续的最小权限方案可以独立演进。

受华为当前能力与流程限制，我们暂时无法公开提供全部相关票据。我们正在与华为沟通，希望让用户能够获得仅与推送相关的最小权限票据。

## 当前限制

为避免测试阶段被误用，同一 PushKit Token 每个自然日最多允许 20 次发送尝试。该限制仅保存在当前 HA 进程内，重启会重置，也不会跨 HA 实例同步；它是善意防滥用措施，不是安全或授权边界。

请不要滥用或恶意推送。异常推送行为可能触发华为 Push Kit 的风控，给整个项目带来重大损失，甚至可能导致 App 被下架。这不是我们希望看到的结果。
